# Hierarchical Fusion Obstacle Avoidance for Outdoor Mobile Robots

Companion repository for the paper:

> **A Three-Level Hierarchical Fusion Framework for Obstacle Avoidance in Outdoor Mobile Robots
> Integrating Vision, LiDAR and Geometric Boundary Constraints.**
> Yinggen Guan, Feilong Fang, Yangyang Zhang, Jun Pei, Ning Jiang.
> *Sensors* (MDPI), 2026. DOI: [to be added upon publication]

## Overview

This repository contains the simulation assets, run data, and analysis scripts for the fusion
obstacle-avoidance framework reported in the paper. The framework fuses **decisions** from three
modalities in a single deterministic decision layer: YOLOv8n-based visual direction estimation,
sector-based 2D LiDAR distance extraction, and Shapely-based geometric boundary constraints
(vision nominates, LiDAR verifies, geometry vetoes).

## Repository contents

```
├── data/                     # raw experimental logs (10 runs, Gazebo Classic + ROS 2 Humble)
│   ├── sciB_main_rect6_fusion_r1 ... r3/       # proposed framework (n = 3)
│   ├── sciB_main_rect6_nav2_r1 ... r3/         # Nav2 DWB baseline (n = 3)
│   ├── sciB_ablation_rect6_laser_only_r1, r2/  # vision channel disabled (n = 2)
│   └── sciB_ablation_rect6_no_boundary_r1, r2/ # boundary constraint disabled (n = 2)
├── scripts/                  # analysis scripts (metrics M1–M7, Tables 1–2, Figure 3)
├── worlds/                   # Gazebo lawn world (10.8 m × 10.8 m, rect6 task)
├── params/                   # Nav2 / planner / fusion-avoidance parameter files
└── src/                      # auto_mower_nav ROS 2 package (7 nodes, Python)
```

Each `data/<run>/` folder contains:

| file | content |
|---|---|
| `odom.csv` | 50 Hz ground-truth trajectory (`t, x, y, yaw`, world frame; boundary = [-3,3]²) |
| `planned_path.csv` | coverage waypoints (`x, y`) generated by the boustrophedon planner |
| `scan.csv` | LiDAR sector statistics logged during the run (front/left/right minima per scan) |
| `run_params.yaml` | full parameter set of the run (Nav2, planner, fusion-avoidance thresholds) |
| `meta.json` | run configuration: boundary polygon, obstacle footprints (center + radius), tags |
| `launch.log` | ROS 2 launch log of the run |

## Reproducing the reported results

- **Figure 3** (representative trajectories) is rendered directly from `odom.csv` and
  `planned_path.csv` of runs `sciB_main_rect6_fusion_r2`, `sciB_main_rect6_fusion_r1`,
  `sciB_main_rect6_nav2_r2`, and `sciB_ablation_rect6_laser_only_r2`.
- **Tables 1 and 2** (metrics M1–M7: success, collisions, min. obstacle distance, stuck events,
  boundary violations, coverage ratio, duration/path length) are computed by `scripts/analyze.py`
  from the same files. All metrics in the paper are per-run values over n = 2–3 repetitions.
